## 风险与覆盖

| 风险 | 自动化验证 |
| --- | --- |
| 无效文件污染任务数据 | 不支持格式 415、损坏 PNG 422、超限 413；错误目录清理 |
| 超大切片网格耗尽内存 | 模拟 1000001×850001 像素尺寸，采样坐标数量固定、边界正确 |
| 背景被解释为病变 | 纯白图片分析完成，组织图块及区域列表为空 |
| 不合法参数/不存在层级 | 参数 422；有效范围内但不存在的层级进入 failed |
| 报告缺乏可追溯性 | 模式、坐标、覆盖率、工具轨迹、图像与报告导出端到端验证 |
| 未生成报告就追问 | 409；不存在任务 404；空问题 422 |
| 暴露源文件 | 资产接口只允许 thumbnail.png 和 heatmap.png |
| 训练数据泄漏 | 同一 patient_id 出现在不同 split 时拒绝执行 |
| 公开样本来源混淆 | 校验官方压缩包；保留来源索引与类别；公开划分模式显式标记，不伪造患者 ID |
| 评估指标错误 | 已知混淆矩阵核对；无阳性样本返回 null；NaN 分数拒绝 |
| 远程模型不可靠 | Mock HTTP 验证两轮工具调用、503 本地回退、工具白名单 |
| 服务重启任务假成功 | 持久化中的运行任务重启后转为 failed |

大尺寸网格测试不等同于真实数 GB 切片性能测试。模型服务测试使用 Mock，不证明真实账号的 endpoint 和权限可用。

## 手工验收

1. 打开工作台，点击合成样本；应出现组织图像、覆盖率、区域表格和报告。
2. 关闭/开启热力图，调整透明度与缩放；原图仍可查看。
3. 点击高分区域坐标，出现黄色框；尝试质量/区域问题并检查证据来源。
4. 下载 Markdown / JSON，核对分析模式和局限。
5. 上传有效图像，点击开始分析；失败时显示可理解的错误。
6. 切换历史任务时，旧任务的异步响应不应污染新任务问答。

## 本次工程验证记录（2026-09-21）

- Windows / Python 3.12：核心链路、异常输入、问答工具调用测试通过。
- 使用程序生成的两层 tiled TIFF 实际调用 OpenSlide，并在第 1 层分析，验证坐标映射。
- 使用六张合成图块运行 PyTorch 一轮训练、保存/加载权重并推理；这仅验证代码链路，不构成模型效果证据。
- Vue 生产构建通过，浏览器中已观察到合成样本分析、热力图和三类问答结果。
- Docker/Compose 文件已提供；本机没有 Docker，未做本地容器启动验证。
- DeepSeek `deepseek-flash` 使用合成报告完成真实工具调用验证，成功调用报告和质控工具并返回回答；远程调用不放入 CI，避免消耗凭据额度。
- 真实医院切片、远程千问 API、临床性能尚未验证。
- 已校验官方 PathMNIST 压缩包，在 900 / 270 / 270 图块子集上运行五轮训练；真实结果及未检出阳性的失败说明已保存到 `examples/pathmnist/`。未将该实验作为临床能力证明。
